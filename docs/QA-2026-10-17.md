# QA pass - 17/10/2026 (two weeks before departure)

Hadar asked for end-to-end QA: no surprises on the trip, no core feature
falling over. Focus: offline (documents, itinerary, emergency), bookings and
budget, guests and permissions, kids/stories/podcast.

## How

- **Code:** typecheck, lint, 571 unit tests, production build.
- **Database:** all 55 migrations on a fresh Postgres + the RLS harness
  (`scripts/rls/run.sh`), 193 probes.
- **Live (read-only):** Supabase advisors, migration history, cron jobs and
  their runs, backups bucket, edge function versions, the trip's real data.
  Vercel runtime logs were not reachable (403 on the team scope).
- **End to end:** a production build against a stand-in that keeps the
  database real - local Postgres with every migration and policy, PostgREST
  (the server Supabase runs) and a small gateway that answers auth from a
  signed JWT. Storage, Edge Functions and Realtime are stubs. Fixture shaped
  like the live trip: 230 days from 31/10 (Vietnam, Cambodia, Thailand,
  Philippines, Japan, Georgia), bookings incl. a cancelled one, expenses in
  VND/USD/ILS, documents, a checklist, kid photos in each approval state, a
  guest story, a family-only journal entry, a join link. Playwright at 390px,
  browser clock set to 02/11/2026 10:00 in Hanoi (trip day 3).
  - Crawl: 29 routes x parent, kid, guest, signed out. Per page: JS errors,
    failed API calls, RTL, horizontal overflow, error text, and a list of
    fixture strings that must never appear for that role.
  - Offline: open the screens online, cut the network, reload each one.
  - Flows: add an expense online and offline, approve then share a kid photo,
    join through the link and get approved.

## Found and fixed

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | High | **An expense added offline was saved twice** when the signal came back. `OfflineSync` replays on `online`, `focus` and `visibilitychange`, which fire together; each replay read the queue before any deleted from it. | One replay at a time (`lib/offline/queue.ts`); test reproduces the double insert. |
| 2 | High (security) | **Kids and guests could read the overall budget** (`trips.total_budget`, ₪180,000 live) from the API. Hard rule 2. | Migration 00056: owner-only `trip_budget` table, column dropped. Probe 56 (11 checks). |
| 3 | High | **A guest's first open after approval showed the parents' home screen**, with "₪180,000 left for the trip". The member store asked "who am I?" before AuthGate linked the account. | AuthGate re-reads the member after linking; Today never renders the parents' view while the member is unknown. |
| 4 | Medium | **The phrasebook opened on the alphabetically first language** - with the live data, Japanese while in Vietnam. Rule 9. The emergency page had the same bug (F5) and was fixed; the phrasebook was not. | Opens on today's country's language (or the next country's before the trip), else the first. |
| 5 | Low | **Checklists offline said "no lists yet - start a new one"** under a banner saying the data was on the device. | Cache-first like budget/itinerary/documents. |

After the fixes, everything above was re-run: the offline expense lands once,
the new guest lands on the guest portal, the phrasebook opens in Vietnamese on
a Vietnam day (online and offline), checklists show offline, the parent still
sees the ₪180,000 target. Unit tests 576/576, RLS 204/204, crawl clean.

## Deploy

1. ✅ **Live 18/10:** `trip_budget` created, the budget copied, the old column
   emptied and pinned to NULL. Kids and guests can no longer read it.
2. **Hadar, in the Supabase SQL editor** (the connector cannot run a column
   drop from here):
   ```sql
   alter table public.trips drop constraint if exists trips_total_budget_moved;
   alter table public.trips drop constraint if exists trips_total_budget_check;
   alter table public.trips drop column total_budget;
   insert into supabase_migrations.schema_migrations (version, name)
   values ('20261018043731', '00056_trip_budget_owner_only');
   ```
3. Merge (Vercel deploys).
4. Redeploy `backup-weekly` (adds `trip_budget` to the weekly dump).

Until 3, the production app shows the parents a total derived from the
categories instead of the ₪180,000 target (the old code reads the emptied
column), and setting a new target from the old app is refused by the pin.
Nothing else changes. Steps 2 and 3 can run in either order.
