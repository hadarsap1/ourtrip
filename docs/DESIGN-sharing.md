## 1. בלוג ("סיפורים מהדרך")

### מה זה
פוסט = כותרת, טקסט, כמה תמונות, יום במסלול ומקום ברמת עיר ומדינה.
לכל פוסט יש רמת חשיפה אחת: `family` / `guests` / `public`. ברירת המחדל היא `family`,
כמו כל דבר אחר באפליקציה (DECISIONS #5).

היומן הקיים נשאר יומן אישי (בעיקר של הילדים). בכל רשומת יומן יהיה כפתור "הפוך לפוסט"
שיוצר טיוטת פוסט ממנה. כך הילד כותב, ההורה עורך ומחליט אם ומתי זה יוצא.

### פוסטים של הילדים
- ילד יכול לכתוב טיוטה. היא נכנסת לתור אישור, כמו התמונות היום.
- רק הורה מאשר ומחליט על רמת חשיפה. טריגר במסד הנתונים מונע מילד לשנות את שדות
  האישור והחשיפה (אותו דפוס כמו `journal_guard_kid` ו-`photos_guard_update`).
- **פוסט שילד כתב לא יכול להיות `public`**, רק `guests` לכל היותר. זה נאכף במסד הנתונים.

### הבלוג הפתוח: מגבלות בטיחות
1. **רק הורה** מפרסם פוסט פתוח.
2. **בלי מיקום בזמן אמת.** בפוסט פתוח מופיעים רק עיר ומדינה, ואפשר לסמן "פרסם אחרי
   שעזבנו". לא מפרסמים מלון.
3. **הבית בארץ ריק.** פוסט פתוח שמכריז "אנחנו בחו"ל לחצי שנה" הוא מידע שימושי לפורץ.
   הדף הפתוח לא מופיע במנועי חיפוש (`noindex`), וההמלצה היא לא לכתוב בו שמות מלאים,
   שם בית ספר או כתובת.
4. **בלי תגובות ובלי לייקים בבלוג הפתוח** בגרסה הראשונה. תגובות אנונימיות = ספאם.
5. **התמונות מועתקות, לא נחשפות.** הדלי `photos` נשאר פרטי. כשמפרסמים פוסט פתוח,
   התמונות שלו מועתקות (מוקטנות) לדלי ציבורי נפרד, ונמחקות ממנו כשמבטלים את הפרסום.
   כך שום דבר אחר בדלי הפרטי לא נגיש מבחוץ, גם אם יש טעות בקוד.

### מסד נתונים (מיגרציה עתידית)
```sql
create type post_visibility as enum ('family','guests','public');
create type post_status as enum ('draft','pending','approved');

create table posts (
  id uuid primary key default gen_random_uuid(),
  trip_id uuid not null references trips(id),
  author_id uuid not null references members(id),
  title text not null,
  body text not null,
  day_id uuid references itinerary_days(id) on delete set null,
  place_label text,            -- עיר / מדינה בלבד
  country_code text,
  status post_status not null default 'draft',
  visibility post_visibility not null default 'family',
  publish_after timestamptz,   -- "פרסם אחרי שעזבנו"
  public_slug text unique,     -- רק לפוסטים פתוחים
  approved_by uuid references members(id),
  published_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table post_photos (
  post_id uuid not null references posts(id) on delete cascade,
  photo_id uuid not null references photos(id) on delete cascade,
  position int not null default 0,
  public_path text,            -- העותק בדלי הציבורי, אם הפוסט פתוח
  primary key (post_id, photo_id)
);
```

### RLS
| תפקיד | posts | post_photos |
|---|---|---|
| owner | הכל | הכל |
| kid | קריאה של פוסטים `family`/`guests` שאושרו ושל הטיוטות שלו. כתיבה רק לטיוטות שלו. טריגר נועל `status`/`visibility`/`approved_by` | לפי הפוסט |
| guest | קריאה כש-`status='approved'` ו-`visibility in ('guests','public')` ו-`publish_after` עבר | לפי הפוסט. תמונה מוצגת רק אם היא עצמה `approved` + `shared_with_guests` |
| anon (לא מחובר) | קריאה כש-`visibility='public'` ו-`status='approved'` ו-`publish_after` עבר | רק `public_path`, דרך הדלי הציבורי |

שאלה פתוחה: האם פוסט `guests` מצרף אוטומטית את התמונות שלו לשיתוף, או שעדיין צריך לסמן
כל תמונה? ההמלצה: כשהורה מאשר פוסט לאורחים, המסך מציע "שתף גם את 4 התמונות" בלחיצה אחת.
זו עדיין פעולה מפורשת של הורה, בלי דגל אוטומטי.

ביטחון בסעיף: 0.75. מה שעלול להשתנות: האם עדיף להרחיב את `journal_entries` במקום טבלה חדשה.

## 2. פודקאסט הילדים

### מה זה
פרק = כותרת, תיאור קצר, קובץ שמע, אורך, מדינה ויום, ותמונת שער אופציונלית.
רק לאורחים (הרשימה המסודרת). **אף פעם לא פתוח** - זה קול של ילדים.

### הקלטה
- מסך הקלטה פשוט בטאבלט: הקלט / השהה / האזן / הקלט מחדש. הגבלה של כ-7 דקות לפרק ❌
  (מספיק לפרק קצר ומונע קבצים כבדים).
- ההקלטה נשמרת קודם במכשיר (IndexedDB) ועולה כשיש רשת. ככה אפשר להקליט באוטובוס או
  בטיסה.
- טכנולוגיה: `MediaRecorder` של הדפדפן. **בלי ספרייה חדשה.**
- בגרסה הראשונה הפרק הוא הקלטה רציפה אחת עם השהיות. חיבור של כמה קטעים ("פינה של עומר,
  פינה של...") אפשרי בהמשך.

### אישור
אותו מסלול כמו תמונות, בשני צעדים נפרדים ונאכף בטריגר:
1. הורה מאזין ומאשר (`status = approved`).
2. הורה מסמן "שתף עם האורחים" (`shared_with_guests = true`).

אורח שומע פרק רק כששני התנאים מתקיימים.

### סיכון טכני שצריך לבדוק לפני הבנייה ❌
טאבלט אנדרואיד מקליט בדרך כלל `webm/opus`, ולא ברור שכל אייפון של סבתא או של הורה
מהכיתה ינגן את זה. לפני שבונים אני מציע בדיקה קצרה (חצי יום): להקליט בטאבלט ולנגן
באייפון ובאנדרואיד. אם יש בעיה, מקליטים ב-`audio/mp4` כשהדפדפן תומך, או ממירים
בצד השרת.

### נפח ❌
בערך 1-1.5MB לחמש דקות. 50 פרקים = פחות מ-100MB. נכנס בנוח במכסת האחסון של Supabase.

### מסד נתונים
```sql
create table episodes (
  id uuid primary key default gen_random_uuid(),
  trip_id uuid not null references trips(id),
  recorded_by uuid not null references members(id),
  title text not null,
  description text,
  file_path text not null,         -- דלי פרטי 'audio'
  duration_seconds int,
  day_id uuid references itinerary_days(id) on delete set null,
  country_code text,
  cover_photo_id uuid references photos(id) on delete set null,
  status photo_status not null default 'pending',
  shared_with_guests boolean not null default false,
  approved_by uuid references members(id),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

### RLS
| תפקיד | episodes | דלי `audio` |
|---|---|---|
| owner | הכל | הכל |
| kid | קריאה של כל פרקי המשפחה. יצירה כשהוא המקליט. טריגר מכריח `pending` + לא משותף, ונועל את השדות האלה בעדכון | העלאה וקריאה. בלי מחיקה |
| guest | קריאה רק כש-`approved` **וגם** `shared_with_guests` | אף פעם ישירות. רק קישור חתום וזמני |
| anon | כלום | כלום |

ביטחון בסעיף: 0.8, בכפוף לבדיקת פורמט השמע.

## 3. רשימת האורחים: להזמין 80 איש בלי לסבול

היום מזמינים אורח אחד בכל פעם. עם 2 כיתות ומשפחה זה כ-80 הזמנות ❌.

- **הזמנה מרוכזת**: מדביקים רשימת מיילים (למשל מקבוצת ההורים) ויוצאות כל ההזמנות.
- **תוויות**: `משפחה` / `כיתה של X` / `חברים`. לניהול ולשליחה בלבד: כל האורחים רואים
  הכל (הוחלט 13/10).
- כל אורח נכנס פעם אחת בקישור מהמייל, והחיבור נשמר.
- מגבלת שליחה של Resend בחינם: כ-100 מיילים ביום ❌. מספיק, אבל כדאי לפצל את ההזמנה
  לשני ימים אם יש יותר.

זה השלב הכי קטן והכי חשוב לפני היציאה: בלעדיו הפודקאסט והבלוג לאורחים לא מגיעים לאף אחד.

## 4. תגובות ולייקים

- אורחים יכולים לשים לייק (סט קבוע של אימוג'י) ולכתוב תגובה על פוסט או פרק.
- **הילדים רואים לייקים עם שם** ("סבתא ❤️", "יואב 👏"). זה לא ערוץ שאפשר לכתוב בו,
  אז אפשר להראות אותו בלי לפרוץ את DECISIONS #18, וזה הדבר שהכי ישמח את הילדים.
- **תגובות כתובות מגיעות לילדים רק דרך הורה** שלוחץ "הראו לילדים", בדיוק לפי הצעת
  הגשר (`DESIGN-wall-bridge.md`). התגובה מועתקת לפיד המשפחה ולא נפתחת לה הרשאה חדשה.
- בבלוג הפתוח אין תגובות ואין לייקים (סעיף 1).

```sql
create table reactions (
  id uuid primary key default gen_random_uuid(),
  trip_id uuid not null references trips(id),
  member_id uuid not null references members(id),
  post_id uuid references posts(id) on delete cascade,
  episode_id uuid references episodes(id) on delete cascade,
  emoji text not null check (emoji in ('❤️','😂','😮','👏','🌍')),
  created_at timestamptz not null default now(),
  check ((post_id is null) <> (episode_id is null))

-- תגובות כתובות: טבלת comments באותו מבנה, עם body במקום emoji
```

RLS: אורח קורא וכותב לייקים ותגובות רק על פריטים שהוא רשאי לראות, ומוחק רק את שלו.
ילד קורא לייקים בלבד, **בלי גישה ל-`comments` בכלל**. הורה רואה הכל.

## 5. איך אנשים יודעים שעלה משהו חדש

ההמלצה לגרסה הראשונה: **כפתור "שלח לווטסאפ"** אחרי כל פרסום.
בטלפון הוא פותח את חלון השיתוף של המכשיר (`navigator.share`), ובמחשב קישור `wa.me`.
ההודעה כתובה מראש בעברית, למשל: "פרק חדש בפודקאסט: עומר ונועה בשוק הצף 🎧 [קישור]".
אתם בוחרים לאיזו קבוצה לשלוח: משפחה, כיתה או חברים.

- עלות אפס, בלי ספרייה חדשה, וכולם כבר שם.
- אופציה בהמשך: מייל סיכום שבועי לאורחים ("השבוע ב-OurTrip: 3 סיפורים, פרק אחד").
  לא בגרסה הראשונה.
