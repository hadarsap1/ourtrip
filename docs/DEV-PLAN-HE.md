> **הערה (2026-07-16):** זהו מסמך התכנון המקורי (בשם הקודם TripHub), נשמר כרקע.
> המסמכים הקנוניים הם `SPEC.md`, `SCHEMA.sql`, `ROADMAP.md`, `DECISIONS.md` - במקרה של סתירה, הם גוברים.

## 1. חזון ומטרה

מרכז פיקוד אחד לטיול המשפחתי: תכנון דינמי, הזמנות, תקציב, מסמכים, מזג אוויר, מפות - וחוויה נפרדת לילדים (יומן מסע, תמונות, הודעות) עם שיתוף מבוקר למשפחה בארץ.

**עקרונות מנחים:**
- דינמיות מעל הכל - הטיול משתנה, האפליקציה חייבת לתמוך בשינוי מהיר של כל דבר
- Offline-first לדברים קריטיים (מסמכים, מפות, מסלול היום)
- אבטחה בשכבות - שלוש רמות הרשאה ברורות
- עלות תפעול: 0 עד ~10$ לחודש

## 2. משתמשים והרשאות

| תפקיד | מי | מה רואה | מה עורך |
|---|---|---|---|
| Owner | הדר + סיון (Google OAuth) | הכל | הכל |
| Kid | טאבלט הילדים (פרופיל ייעודי) | מסלול היום, יומן, תמונות, תיבת הודעות | יומן משלהם, העלאת תמונות, הודעות |
| Guest | מיילים ספציפיים דרך לינק הזמנה | רק מה ששותף: תמונות נבחרות, יומן, מסלול "שבוצע", הודעות | שליחת הודעות בקיר המשפחתי |

**מודל האבטחה:**
- Supabase Auth עם Google OAuth ל-Owners
- Kid profile: כניסה בקוד PIN פשוט על מכשיר שאושר מראש על ידי Owner (device registration)
- Guests: הזמנה במייל עם magic link. הלינק כפוף לרשימת מיילים מאושרת - לינק שהועבר הלאה לא יעבוד עם מייל אחר
- Row Level Security (RLS) על כל טבלה - ההרשאות נאכפות בשכבת ה-DB, לא רק ב-UI
- מסמכים רגישים: Supabase Storage עם signed URLs קצרי מועד, גישה ל-Owners בלבד
- כל פריט תוכן (תמונה, פוסט יומן, יום במסלול) נושא דגל `shared_with_guests` - שיתוף הוא תמיד opt-in ידני

## 3. ארכיטקטורה טכנית

```
┌─────────────────────────────────────────┐
│ PWA (Next.js 14 + React)                │
│  - RTL עברית, Tailwind                  │
│  - Service Worker (offline cache)       │
│  - IndexedDB (נתונים אופליין)           │
└──────────────┬──────────────────────────┘
               │
┌──────────────┴──────────────────────────┐
│ Supabase                                │
│  - Auth (Google OAuth + magic links)    │
│  - Postgres + RLS                       │
│  - Storage (מסמכים, תמונות)             │
│  - Realtime (סנכרון בין מכשירים)        │
│  - Edge Functions (הזמנות מייל, APIs)   │
└──────────────┬──────────────────────────┘
               │
┌──────────────┴──────────────────────────┐
│ APIs חיצוניים                           │
│  - Open-Meteo (מזג אוויר, חינם)         │
│  - open.er-api.com / exchangerate.host  │
│    (שערי מטבע גלובליים, חינם;           │
│     Frankfurter כגיבוי)                 │
│  - Google Maps JavaScript API           │
│  - Anthropic API (המלצות מקומיות)       │
└─────────────────────────────────────────┘
```

**החלטות מפתח:**
- **PWA ולא נייטיב**: התקנה על כל המכשירים (כולל טאבלט הילדים), עדכונים מיידיים בלי חנות, יכולות אופליין מלאות דרך Service Worker
- **Next.js על Vercel**: הסטאק שאתה כבר עובד איתו, דיפלוי בפוש אחד
- **Supabase Realtime**: כשסיון מעדכנת את המסלול, אתה רואה את זה מיד - קריטי לדינמיות
- **סנכרון offline**: כתיבה אופליין נשמרת ב-IndexedDB עם תור סנכרון, מתנגנת לשרת כשחוזר חיבור. קונפליקטים: last-write-wins עם התראה

## 5. פירוט הפיצ'רים

הפירוט המלא והמחייב נמצא ב-`docs/SPEC.md`. עיקרי הפיצ'רים:

- **מסלול**: תצוגת "היום" כמסך ראשי, ציר זמן עם גרירה, שינוי תוכנית בשתי הקשות
- **הזמנות**: הזנה מהירה + צירוף PDF, שדות חכמים לפי סוג, קישור אוטומטי למסלול ולתקציב
- **תקציב**: קטגוריות, הזנת הוצאה בשלוש שניות, שערים חיים, דשבורד עם קצב שריפה ותחזית
- **מזג אוויר**: Open-Meteo לפי מיקום כל יום, התראת גשם על פעילות חוץ
- **המלצות**: "מה בסביבה" מבוסס Claude API + Google Places
- **כספת מסמכים**: Owners בלבד, signed URLs, דגל "זמין אופליין"
- **מפות**: פינים לפי יום, מסלולים שמורים, snapshot אופליין של מפת היום
- **חוויית הילדים**: יומן מסע עם עידוד יומי, תמונות עם תור אישור הורים (+ שיתוף לאורחים כצעד נפרד), מד דמי כיס, קיר הודעות משפחתי
- **פורטל המשפחה**: דף צפייה נקי בלי התקנה - תמונות ששותפו, יומן, מפת "איפה היינו", שליחת הודעה
- **רשימות אריזה וצ'קליסטים**, **דף חירום לפי מדינה** (אופליין, הקשה אחת), **שיחון לפי שפה** (אופליין, מצב "הצג למקומי"), **התראות חכמות** (Web Push), **Where's the car**

**הוחלט להשאיר בחוץ (אפשר לחזור אחרי הטיול):**
- ספר זכרונות PDF - הנתונים נשמרים כך שאפשר לייצר אותו גם בדיעבד
- מעקב טיסות חי - ההזמנה כוללת קישור מהיר לדף הטיסה
- חילוץ הזמנות ממייל אוטומטי (backlog)

## 6. תוכנית פיתוח - 8 שבועות

ראו `docs/ROADMAP.md` לקריטריוני הקבלה המלאים. אבני הדרך:

1. **שבוע 1 - תשתית ושלד**: שניכם מחוברים ורואים מסך "היום" ריק
2. **שבוע 2 - מסלול והזמנות**: אפשר להתחיל להזין את הטיול האמיתי
3. **שבוע 3 - תקציב, מטבעות וצ'קליסטים**: רושמים הוצאות קיימות ורשימת אריזה ראשונה
4. **שבוע 4 - מסמכים + אופליין**: מצב טיסה - הכל הקריטי נגיש בלי אינטרנט
5. **שבוע 5 - מפות, מזג אוויר וכלי שטח**: תצוגת "היום" מלאה
6. **שבוע 6 - חוויית הילדים**: הילדים כותבים פוסט ראשון בהרצה ביתית
7. **שבוע 7 - פורטל משפחה והודעות**: הזמנת סבא וסבתא לפיילוט
8. **שבוע 8 - המלצות, התראות, הקשחה וריצת בדיקה**: מוכנים לטיול

**הערת תכולה לשבוע 8:** זה השבוע העמוס ביותר. אם נדרש לצמצם - ההתראות יורדות ראשונות, ההקשחה והבדיקות לא זזות.

## 8. סיכונים ונקודות תשומת לב

1. **אחסון תמונות** - אם הילדים יעלו הרבה, 1GB ייגמר. פתרון: דחיסה בצד לקוח לפני העלאה + מגבלת "תמונות נבחרות" (זה גם פיצ'ר, לא באג - לבחור את הרגעים)
2. **אופליין אמיתי הוא החלק הקשה** - לתעדף: מסמכים ומסלול היום חייבים, שאר הסנכרון הדו-כיווני זה בונוס. לא להיתקע על זה בשבוע 4
3. **הטאבלט של הילדים** - לוודא שה-PWA עובד טוב על המכשיר הספציפי לפני שבוע 6
4. **Scope creep** - הרשימה בסעיף 5 מפתה. להיצמד ל-ROADMAP
5. **גיבוי** - ייצוא שבועי אוטומטי של ה-DB, כי אלה זכרונות של פעם בחיים
6. **אימות ילדים (JWT מותאם)** - החלק הארכיטקטוני הקשה ביותר; לתכנן את `current_member()` כבר בספרינט 1
7. **טיול מסביב לעולם** - מטבעות רבים, שפות רבות, דפי חירום לפי מדינה - שום דבר לא מניח יעד יחיד
